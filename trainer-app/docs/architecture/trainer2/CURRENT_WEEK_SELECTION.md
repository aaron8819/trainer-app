# Current-week workout selection and Program review

Planning owns eligibility in `src/lib/engine/trainer2/occurrence-resolution.ts`. A programmed week is a contiguous run of the same stage UUID in immutable authored occurrence order, matching `orderedWorkoutGroups`. Stage names, stage-array position and recurring stage UUIDs do not identify a week or workout. The current week is the run containing the first unresolved occurrence. Finish and explicit Skip remain the only terminal resolution facts; Discard leaves an occurrence unresolved. All saved occurrences count, including optional-only workouts. A week advances only when every occurrence in that run is Finished or Skipped.

`src/lib/api/trainer2/execution.ts` owns the authorized start/read adapters. ReadNext retains its recommended first unresolved occurrence and adds `eligibleOccurrenceIds`: every unresolved UUID in the current week. Completed plans return an empty list. The read contract validates unique pending membership and inclusion of the recommendation. Its optional field permits older readers/tests to use the first-only recommendation safely; current servers always emit the list. Selection does not rewrite that recommendation or create a command.

Start accepts any exact eligible occurrence in the approved revision, capturing its unchanged prescription and source/owned identities through the existing START owner. Different-week, finished/skipped, foreign and stale requests fail without domain changes. Account locking, exact durable outcomes, one ordinary attempt per occurrence and the partial one-Open-per-account index remain. Any account-owned Open execution prevents another start. Replay precedes current eligibility checks and never revives a discarded/finished attempt. The explicit Skip command uses the same current-week eligibility and rejects any account-wide Open execution; its conservative accepted-sequence/revision binding and exact pending recovery remain.

`TrainingOverview` presents all current-week workouts as Pending, In progress, Completed or Skipped. `Workout` initially selects the recommendation. An explicit selection changes only local UI state; preview and Start are separate. The start/skip envelopes bind that selected UUID. With an Open workout, Resume is offered and Start is absent. Completed results link to their saved execution; skipped prescriptions and provenance remain reviewable. Program has keyboard-operable week buttons, one visible week, single-column phone cards and two desktop columns. Exercise variation details use native disclosure. Controls have 44px minimum height. Focus stays on deliberate selection/navigation controls. The V1-style active logger, additions, swaps, history, prefill and explicit finish owner are unchanged. Confirmed Finish returns home and starts nothing.

Reload loads authoritative state while retaining exact pending Start/Skip commands. Returning focus to Training/Program refreshes current state unless command/review delivery is locked. Read generations and accepted-sequence comparison reject delayed older reads. An uncertain start keeps Check again and does not substitute the current selection into its saved envelope. SessionStorage remains the existing browser durability boundary; device loss/full offline synchronization are outside this slice.

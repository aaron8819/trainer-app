# Exercise swapping

Execution & Evidence owns today-only exercise changes in `src/lib/api/trainer2/exercise-swap.ts`. Strict contracts live in `src/lib/trainer2-contracts/exercise-swap.ts`; pure eligibility, START-based target derivation and effective read models live in `src/lib/engine/trainer2/exercise-swap.ts`.

An Open workout position is eligible only while every execution-owned target has no retained result revision and no explicit skip. Clearing results never unlocks a position. Repeated changes and Return to original append revisions while untouched. Positions, target IDs, set count/order/classification/required status, role, target RIR, authored rest and accepted plans never change. Every revision derives from immutable START, preventing accumulated target drift. Compatible purpose/rep basis retains original ranges; incompatible replacements use the reviewed Trainer2 catalog defaults. Replacement numeric loads are always blank targets. Returning to original restores its captured targets and prescribed load.

## Preview and acceptance

`POST /api/trainer2/executions/swap-exercise-preview` uses the restricted read role in a repeatable-read read-only transaction. It does not renew a session or write facts. It returns the replacement snapshot, every resulting target, reviewed position binding, instruction epoch, effective hash and advisory compatible historical load in rounded pounds. Preview and acceptance check existing explicit exclusions through the instruction owner, including scoped exceptions.

`POST /api/trainer2/executions/swap-exercise` accepts `SwapExercise` with the established action/device/account/ownership/dependency envelope. Expected state binds START hash, position assignment, instruction epoch and preview effective hash. Acceptance rechecks ownership, Open lifecycle, position membership, all retained result/skip history and reviewed content under the existing account-first lock. It atomically appends one revision, sequence and durable outcome. Exact retries remain recoverable after finish; changed envelopes under the same action ID conflict. Independent positions have independent expected versions.

RecordSetResult and SkipSet bind the reviewed position assignment. An old version-zero client remains valid only before any swap. Finish and discard bind all positions once a substitution exists. Historical finish facts keep their original representation. If log/skip wins, swap conflicts; if swap wins, stale log/skip conflicts. Finish conflicts with any intervening change; a finished execution rejects new swaps. Same-position competing swaps conflict, while independent untouched positions can both succeed.

Suggestions use pounds rounded to nearest five; stored historical evidence retains units, decimals and zero semantics. Following sets copy only preceding recorded work in their same position. Completed readback identifies the replacement and original exercise. Selection, set counts and timer deadlines remain unchanged by swapping; deliberate successful-change reveal uses the existing timer-aware scrolling.

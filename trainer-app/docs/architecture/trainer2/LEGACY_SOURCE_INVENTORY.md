### Identity, revision and provenance basis

Stable identity is `(source system, legacy account, source family, original record key)`. Values, dates, array position and display names never identify records. `ExerciseEquipment` uses PostgreSQL's JSON-array representation of its two actual composite-key columns; `HypertrophyPlanDraft` uses its `macroCycleId` primary key. Shared catalog rows appear in the capturing account's source namespace and are limited to owner-used exercises/equipment.

The raw version-1 representation is every PostgreSQL column cast directly with `column::text`, stored as string or SQL null. A bounded catalog query enumerates real columns inside the same read transaction; JSONB `null` remains the string `"null"` and cannot collapse into SQL NULL. Thus SQL numeric values never pass through JavaScript Number; Float values retain PostgreSQL's surviving textual value, including nonfinite text if present. SQL NULL is null; an absent fixture column remains absent. Array columns retain PostgreSQL array text. Float output explicitly uses `extra_float_digits=3`. JSONB column values remain PostgreSQL-rendered JSON text, with nested decimals unparsed. Timestamp columns remain timestamp text; no invented timezone is appended. This representation cannot restore original input decimal spelling lost to Float storage, earlier quantization, JSONB whitespace/key order, or overwritten values. Synthetic file decimal strings retain their exact spelling.

Hash domain `trainer2-legacy-source-v1` uses the existing strict recursively key-sorted canonical JSON convention. Arrays are ordered. Family and row order are canonicalized. `payloadHash` binds the full raw row including source family/key. `dependencyHash` binds declared scope and the sorted connected source component: all surviving linked parent/child payloads plus bound external assertions. Components include source seeds/plans, session/set/log trees, catalog rows and captured snapshots. This deliberately conservative basis can revise several sessions when shared source context changes. Cycles are visited once; it is not runtime replay or an inferred correction chain. Unrelated disconnected records do not revise one another.

`revision` binds stable identity, payload hash and dependency hash. Equal values on different source records remain distinct. Same unchanged capture basis produces the same revision; changed source facts/dependencies or external assertions produce a new observed revision. `sourceHash` binds declared scope and sorted identity/revision pairs, including empty captures. Observation batch ID, capture timestamp and PostgreSQL snapshot token are explicitly outside content identity. Reports omit those changing observations; the capture retains them separately. Hashes establish captured-content integrity, not historical truth. Report rendering and scope comparison recompute captures and reject altered raw facts, classifications or hashes.

External assertions preserve exact artifact text, artifact identity, explicit claims and an exact source identity/payload-hash binding. Measurement field confidence records the source field or hashed artifact basis; missing dimensions stay null/unknown. Conflicting assertions stay conflicting. The delivered examples assert synthetic protocol facts only. This mechanism does not authenticate an external witness, qualify real data, or accept history. All rows have `quantitativelyQualified: false`.

## Read transaction and coverage boundary

One `REPEATABLE READ READ ONLY` transaction verifies its actual role and snapshot, then captures every declared database family with fixed parameterized owner filters. Child paths follow owned parents. Shared catalog selection uses only owned workout/template exercise IDs. An owned row may retain a foreign FK value as its own raw fact, but no foreign row is fetched to explain it. Missing/foreign/uninspected links all say unavailable; querying foreign data to distinguish those cases would violate this boundary. An orphan lacking any owner path cannot be attributed or counted as an account record.

The supported visibility guarantee requires source queries to execute without RLS filtering. `readLegacySource` sets `SET LOCAL row_security=off` before any reads. For the restricted non-owner, non-BYPASSRLS reader this **does not bypass policies**: PostgreSQL rejects a query that would be affected by row-level security with SQLSTATE `42501`. Enforcement applies to actual queries, including owner-path joins/subqueries and empty results, instead of relying on a preliminary catalog check that could race with visibility changes. Policy-filtered and default-deny configurations are unsupported. The adapter neither changes policies nor disables table RLS.

An RLS failure rolls back the whole transaction and releases the connection; it returns no capture, and the CLI exits nonzero with empty stdout. Failed captures cannot support completeness or disappearance claims. Successful capture content, owner predicates, scope and comparison semantics remain unchanged. Local fixture verification does not qualify deployed RLS, grants or hosted admission.

The connection must be explicit loopback `trainer2_disposable_*` using `trainer2_legacy_reader`, with no query-string libpq overrides. Runtime rejects actual superuser/bypass/create-role/create-db roles and any role membership (including a NOINHERIT role that could SET ROLE), public-table ownership, table mutation grants or column INSERT/UPDATE grants. No default app pool, account provisioning or environment-file loading is used. Database role grants and schema qualification here are disposable-fixture evidence only.

Per-family limit 500, total 2,000 records, per-row 1 MB, total text 16 MB, at most 256 columns per source table, per-statement 10 seconds and idle transaction 15 seconds. Limits abort the whole capture, with no partial success output. There is no pagination across snapshots in v1; larger authorized scopes require a later bounded export design. All rows are ordered deterministically, independent of database insertion order. Completeness is only within the declared owner-reachable families, never an all-history or all-device statement.

Counts distinguish distinct source records, Workout sessions, SetLog rows (including skipped/unconfirmed), and unique record/discrepancy-code pairs. Multiple discrepancies do not inflate covered records. Reports include scope, hashes, every examined family (including zero rows), classifications, unavailable relationships, exclusions and limitations. Source disappearance is emitted only for equal complete declared scopes; partial capture absence never means deletion. Disappearance never authorizes source or destination mutation.
